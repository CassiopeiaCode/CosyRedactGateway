# 高熵凭据检测 / High-entropy credential detection

[← 中文 README](../README.md) · [English](HIGH-ENTROPY.en.md) · [技术参考](REFERENCE.md)

本文说明高熵凭据检测的实现、既有合成样本结果、验证方法与安全边界。既有结果不等于当前版本的复测成绩；请在自己的检出版本中运行演示与回归测试。本次文档更新未重新运行网关测试，不构成安全审计。

<a id="claim"></a>
路由开关 `H` 对应高熵凭据检测。留空标志位会启用包括高熵检测在内的全部检测器。

## 核心卖点

**高熵检测为符合条件、呈随机形态的字符串增加一条检测路径，不要求已知厂商前缀，也不要求凭据赋值标签。** 全部检测器启用时，它与 Cosy 的结构化检测及 Gitleaks 兼容规则互补。

**“代码交给 AI。凭据，不该跟着走。”** 表达的是保护目标，而不是零泄漏认证。本地部署时，命中的文本会在网关转发前被替换；Cloudflare Workers 和远程 Deno 部署则把处理过程移入另一台主机的信任范围。

具体实现可在 [`worker.js`](../worker.js) 中查看：`parseFlags`、`tokenizeBlocks`、`entropyScore`、`isHighEntropyBlock`、`findSensitiveSpans`、`RedactionContext` 与 `redactJson`。[熵检测校准文档](ENTROPY.md)解释了评分与阈值。

## 高熵检测实际检查什么

高熵检测对超过 8 个字符的 ASCII 字母数字块评分，排除纯数字块；使用英文字符二元组交叉熵、与长度相关的阈值，以及最低字符多样性要求。它不是万能的语义凭据识别器，也不只是“Shannon 熵超过固定数值”。

高熵检测与其他检测器产生的候选会经过重叠／优先级处理后合并。因此，高熵检测是额外的候选来源，不能把全开行为简化为所有检测器互不影响的完美并集。

典型场景是内部服务或复制工具输出中的**无标签随机值**。这些是动机场景，不是针对所有令牌格式的保证。字符串可以敏感但不随机，哈希和标识符也可以看起来随机但并不敏感。

## 纯本地演示

在仓库根目录执行：

```bash
node scripts/demo-high-entropy.mjs
node scripts/demo-high-entropy.mjs --json
```

脚本导入当前检出的 `worker.js`，而不是替换为简化检测器。它对中性上下文中的同一个合成值，比较 `PSIBEG`、仅 `H`、空标志位／全开三种策略，统计候选值内实际被覆盖的字符数，并检查精确还原。短字符串、纯数字串和重复串用于检查高熵检测已说明的排除条件。

**关闭高熵检测的结果来自实际观察，不预设它必然漏检。** 后续版本中的其他规则可能增加覆盖，脚本会报告这种变化，而不是制造差异。如果高熵检测／全开不再满足样例的预期完整覆盖，断言会明确失败。

脚本不联网，不调用模型。它检查导出的检测与文本脱敏函数，不等于 SDK 路由、真实上游或完整 HTTP 网关的端到端测试。README 中的动画是独立的机制示意，不是该脚本的录屏。

## 已有校准，不是新跑出的基准

项目既有文档记录：30,000 个保留自然词拼接样本中，296 个被判为高熵，占 0.9867%；随机 hex/base62 样本的召回率随长度增加。这描述的是给定合成语料与校准，不是真实环境泄漏率。**本次文档更新未复跑这些测试。**

完整回归与报告可在仓库中复现：

```bash
npm test
npm run entropy-report
```

## 如何验证额外的检测覆盖

固定同一个 Cosy 版本和同一组输入，分别观察以下三种策略：

| 策略 | 标志位 | 验证重点 |
| :--- | :--- | :--- |
| 关闭高熵检测 | `PSIBEG` | 记录其他检测器对候选值的实际覆盖，不预设它们一定漏检。 |
| 仅高熵检测 | `H` | 单独观察高熵检测是否命中，以及覆盖了哪些字符。 |
| 全部启用 | 空标志位或 `HPSIBEG` | 检查组合后的覆盖和精确还原，而不只看原字符串是否消失。 |

把合成凭据与正常代码放入相同上下文，并分别检查不同编码和字段位置。记录漏检、部分覆盖、误报及不检查的范围。样例中的额外覆盖需要实际测量，不能直接推广为所有凭据的检测率。

## 程序员需要了解的边界

短、低多样性、低评分、被分隔或编码的凭据可能漏检。分隔符会拆开文本块，因此一个很长的整体值，不一定含有符合高熵检测条件的块。正常标识符、哈希、压缩代码和非英文转写也可能误报。部分 JSON 控制／URL／多模态字段被跳过；JSON 成员名称不是通用脱敏目标。

`Authorization` 与 `x-api-key` 会按设计转发，以完成上游认证。绕过网关的请求、客户端回退路径、周边日志、主机其他流量和远程处理环境，都需要额外控制。脱敏也可能去掉模型完成任务所需的上下文；还原要求占位符已知且未被修改。

**“减少命中正文值的暴露”，不等于“没有任何凭据能够离开主机”。** 本地部署是本地处理的条件，但不等于穷尽检测或整机出口防护。[安全边界](../README.md#security) · [安全策略](../SECURITY.md)

## 定位摘要

面向程序员，以高熵检测对无前缀、无标签随机凭据的额外检测路径为主卖点；全开策略组合高熵检测、结构化检测与 Gitleaks 兼容规则。单文件、零依赖、流式还原是支撑这一工作流的能力，而不是高熵检测的替代品。

保留可检查的实现、可复现的样例，以及误报、漏报和信任边界。先用合成样本验证自己的提示词、代码与工具链，再选择实际策略。
